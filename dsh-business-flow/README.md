# 业务流程分析（dsh-business-flow）— DSH 插件

在 DeepSeek Harness 的左侧栏加一个「业务流程分析」面板：选一个本地项目目录，用自然语言描述一项业务
（例如「会员下单支付的完整链路」「发票审批流程」），由 profile 里**已配置的默认模型**阅读项目，
把这项业务的**数据业务流程**画成拓扑图；再选中图上的某个节点写下粗略需求，插件会把它改写成一段
可以直接交给 Agent 执行的**精准实现 prompt**，并能一键在该项目里新建会话。

## 功能

- **业务流程拓扑图**：节点分 5 类（`entry` 入口、`process` 流程、`data` 数据、`permission` 权限、
  `external` 外部服务），连线分 3 类（`flow` 调用、`data` 读写、`auth` 鉴权）。图一般为 6–20 个节点，
  从入口排到数据落点，节点尽量使用项目里真实的模块和文件名，并附带实现它的相对路径文件。
- **拓扑视图**：工具栏左侧可在「全貌 / 调用链 / 数据 / 权限 / 外部」之间切换。各视图都从同一次分析结果
  在前端过滤得到，不会额外调用模型：调用链保留入口、流程和调用连线；数据保留数据节点、有表的节点和读写
  连线；权限保留权限节点、鉴权连线及受其约束的节点；外部保留外部服务及调用它们的节点。当前分析里没有
  某类内容时，对应按钮置灰；悬停按钮可以看到该视图的节点数。图例只显示当前视图里出现的类别。
- **画布**：分层布局，连线按方向分散接入节点边缘，扇入、扇出不会挤在同一个点上；连线标签
  优先放在不遮挡节点和其他标签的位置，放不下的标签先隐藏，悬停连线或选中节点时再完整显示。
  悬停或选中节点时，会高亮它和直接相连的节点、连线，其余部分淡出。工具栏图例同时说明节点类型和三种连线。
- **缩放**：自动缩放时尽量显示整张图；整张图会小到看不清字时，改为按宽度适配（最多 80%），
  沿纵向滚动。「适应画布」按钮始终显示整张图。选中节点或高亮表后，如果目标不在视野里，会自动
  滚动过去。另有全屏（浏览器全屏不可用时退回页面内最大化）。点击空白处或按 Esc 取消选择。
  按住 Ctrl / ⌘ 滚动滚轮或在触控板上双指捏合，以指针位置为中心缩放；在空白处拖拽可平移画布。
  节点可以用 Tab 聚焦，Enter / 空格选中或取消。
- **涉及的表**：分析时模型会为每个节点列出它直接读写的数据库表，标注读、写或读写；Host 会在节点
  关联文件和图中其他节点的文件里核对表名，找不到的标为「推断」。节点卡片右下角显示表数量；点击
  节点可以看到表清单，点表旁边的「+N 个节点」会在图中高亮所有用到这张表的节点。生成 prompt 时，
  节点涉及的表也会一起交给模型。
- **细化节点 → 精准 prompt**：结合业务名、节点说明、相邻节点关系和关联文件摘录，生成包含目标、
  要改动的文件或符号、期望行为（含数据与权限影响）和验收标准的 prompt（不超过 400 字）。生成后可以
  直接修改，再复制或「在项目中新建会话」使用修改后的内容。
- **进行中的分析**：分析和生成 prompt 时显示已用秒数，可以取消；取消会结束 Host 上对应的 Agent 回合。
  切换到别的侧栏面板再回来，项目、输入、当前图、节点需求和生成中的结果都会保留。
- **导出**：工具栏「导出」可以把当前视图复制为 Mermaid `flowchart`，或下载为独立的 SVG（主题颜色已
  换成屏幕上的实际颜色）。
- **历史记录**：每次分析都会保存（同一业务的多次分析都会保留），可以按业务或项目路径搜索、重新打开、
  用当前项目重新分析并更新、单条删除、按项目删除或全部清空（删除前都会确认）。历史不设上限。
- **对比**：历史里同一项目、同一业务的其他分析旁有「对比」，会列出新增 / 消失的节点和连线（节点按名称
  匹配），新增节点在图上以虚线框标出。
- **服务自检**：面板会显示默认模型是否已配置以及 provider / model 名称；未配置时给出提示。
- 中英双语界面。

## 工作方式

1. Host 端先在本地预扫描项目：跳过 `node_modules`、`.git`、`dist`、`build`、`target`、`.venv`
   等目录，按文件名挑出 controller / service / route / mapper / schema / migration / auth / config
   等候选文件，摘录成索引和关键片段（约 2 万字符以内）。
2. 通过 Harness 的 `agents` 服务为该项目创建一个分析用 Agent（工作目录就是项目根目录，模型取自
   `agentDefaultModel` 的当前选择），用 `sessionController` 提交一轮真实的会话，直到 `turn/end`。
   同一项目复用同一个 Agent，后续细化会延续同一段对话；出错时丢弃，下次重新创建。
   同一 Session 上的请求按顺序逐轮执行；每轮用提交时的 `requestId`（写入用户消息的
   `source.rpcId`）认领自己的 turn，不会拿到其他请求或上一轮残留 turn 的回答。
3. 要求模型只输出一个 JSON 对象；插件从回复中提取并校验节点和连线。如果第一次没有给出节点，会再
   追问一次。单轮最长 8 分钟，关闭面板或断开连接会取消正在进行的那一轮。

> 提示词要求模型「不修改文件、不安装依赖、不运行命令，最多 3 次只读工具调用」，但这只是对模型的
> 约束，插件本身并没有在工具层面禁止写操作。实际权限仍取决于你在 Harness 里的审批或权限预设。

## 安装

这是一个 DSH profile bundle（`cordis.patch.yml` 插入 Host 行 `business-flow`，`package.json#dsh.client`
声明 Client 模块）。

在 Web GUI 的插件管理里选择「从本地目录安装 bundle」，指向本目录即可。安装后 profile 的
`package.json` 里会出现这两项，可以据此核对：

```jsonc
{
  "dsh": { "profile": { "bundles": ["@local/dsh-business-flow"] } },
  "dependencies": { "@local/dsh-business-flow": "link:/path/to/dsh-business-flow" }
}
```

前提：profile 里已配置可用的默认模型（`@deepseek-ai/dsh-agent-default-model`）。

更新 `index.js` 后需要重新启用插件行或重启 DSH；只改 `client.js` 时刷新一次页面即可。

## HTTP 接口

全部挂在 `/api/dsh-business-flow/` 下，只接受来自本机回环地址的请求（校验连接地址、`Host`、`Origin`/`Referer`
和跨站 fetch 元数据），其他请求一律返回 403。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/ping` | 默认模型是否已配置，以及 provider / model |
| POST | `/analyze` | `{projectPath, business, sessionId?}` → 拓扑图 |
| POST | `/draft` | `{projectPath, business, node, graph, requirement, sessionId?}` → `{prompt}` |
| GET | `/history` | 读取历史 |
| POST | `/history/save` | 按 id 合并整份历史（只增改，不删除） |
| POST | `/history/upsert` | 新增或更新一条 |
| POST | `/history/delete` | 删除一条或某个项目的全部记录 |
| POST | `/history/clear` | 清空历史 |

## 数据位置

- 历史记录：`$DSH_HOME/business-flow/history.json`（默认 `~/.dsh/business-flow/history.json`；原子写入；文件损坏时会拒绝写入，避免覆盖丢失）
- 改名前（`bizflow`）的 `~/.dsh/bizflow/history.json` 会在首次读取历史时移动到新位置；新文件已存在时不会覆盖
- 旧版本存在浏览器 `localStorage` 里的记录，会在首次打开时迁移到上述文件

## 目录结构

```

cordis.patch.yml    # 插入 Host 行 business-flow

locale/zh.json, en.json

test/               # node --test：Session 轮次关联（合成事件流）
```

## 已知限制

- 拓扑图质量取决于所配置模型的能力和项目摘录的覆盖面；超大项目只会摘录其中一部分文件。
- 分析结果是模型的归纳，不是静态分析结论，节点和文件对应关系需要人工核对。
- 表名核对只检查表名是否作为完整标识符出现在关联文件里（每次最多读 60 个文件、单个文件不超过
  400 KB，只读项目目录内的文件），不解析 SQL 或 ORM。「已找到」只说明代码里出现过这个名字，
  不代表读写方式一定准确；标为「推断」的表需要人工确认。
- 加入表识别之前保存的历史记录没有表信息，节点详情里会提示点「更新」重新分析。
