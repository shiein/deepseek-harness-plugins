## 规则

- R4 阶段不写新测试，只留 `TODO(test:r4-N)`。T 阶段才补测试。
- 每次提交前：`npm run typecheck` 为 0 错误，`node scripts/check-line-length.mjs` 通过。
  每完成一个工作项，跑一次现有全量 `npm test`，必须全绿。
- 现有测试失败时修代码，不改测试迁就。R4-1 去掉 `lastError` 会导致读它的测试需要调整，这属于有意改变，
  要在提交信息里逐条说明。
- R4 不得改变工具参数、输出字段、诊断码和能力等级。唯一例外是意外失败诊断的 hint 追加日志路径（同步方案 §4.2）。
- 删除或移动任何文件前，先 `grep -rn` 找出代码、`package.json`、文档、AGENTS.md 中的所有引用，在同一提交内一并更新。
- `dsh-page-preview-development-plan.md` 正文不动。只有 R4-4 改动的文件路径引用可以更新。
- 浏览器侧 `src/browser/**` 只能写 ES2018 普通 JavaScript，改完用 `node --check` 检查。
- 新增和修改的代码行不超过 120 字符。
- 进度文档的口径：
  - R4 每项完成后，在 `docs/development-progress.md` §2.6 标"🟨 代码完成，测试待补"，附提交号
  - T 阶段对应测试通过后，才把 R3、R4 各项改为 ✅，并附测试文件名
- 每个工作项至少一个本地 commit。**禁止 push 或发布**，禁止新增依赖，禁止升级 DSH，禁止在任何 DSH profile 中安装。

## 证据要求（上一轮出过问题，务必遵守）

R3 中有一处注释写着"已按锁定版本核实"，实际没有核实，结果也是错的。所以本轮要求：

- 声称"已核实 / 已验证 / 来自某版本"的地方，必须写明具体依据（文件路径与行号、命令及其输出、测试用例名）。做不到就写"未核实"。
- R4-5 判断"脚本已被测试覆盖"时，必须给出覆盖它的测试文件和用例名。
- T 阶段的汇报必须附实际命令输出摘要，包括通过数、失败数、跳过数和平台。
