## 2. 新发现的 P0

### 2.1 Vue CLI 拒绝几乎所有真实项目的 devServer 配置

- **证据**：`src/adapters/vue/cli/dev-server-hook.ts:34,46`。`proxy`、`before`、`port`、`host`、`headers`、`historyApiFallback` 等 16 个键，只要项目配置里出现任何一个，就会抛出 "cannot be previewed"。
- **影响**：Vue 2 + Element UI 的后台项目（例如 vue-element-admin 一类模板）几乎都配置了 `port` 和 `proxy`，很多还用 `before` 挂本地 mock。也就是说，Aesc 的首要目标栈在真实项目上基本打不开。测试样本没有配这些键，所以全部通过。
- **对比**：Vite 路径的做法是"由插件接管并覆盖"（`config.server.proxy = {}`，端口和 host 改为自有值），而不是报错。两条路径的策略不一致。
- **建议**：改为"接管、剥离并记录"。
  - `port`、`host`、`https`、`http2`、`server`、`allowedHosts`、`public`、`headers`：由插件覆盖为自有值。
  - `proxy`、`before`、`after`、`setupMiddlewares`、`onBefore*`、`onAfter*`：直接移除，不执行。
  - `historyApiFallback`：按预览页规则重写。
  - 每个被移除或覆盖的键都写进 `knownDifferences`，并输出一条诊断，告诉 Agent 业务数据需要改用场景 fixture。
  - 只有异步配置导出这类确实无法处理的情况才报错。

### 2.2 Vue CLI 路径改完代码后页面不更新，Agent 也无法刷新

- **证据**：`cli/dev-server-hook.ts:56-67` 设置了 `hot: false`、`liveReload: false`、`webSocketServer: false`；而 `src/host/tools/` 只有 open、status、capture、stop 四个工具，Runner 已有的 `refresh` 没有暴露。
- **影响**：Agent 修改 Vue 2 页面后，webpack 会重新编译，但浏览器里仍是旧页面，`freshness` 一直停在 `unverified`。P1-6 的 `current` 在 CLI 路径上只能靠用户手动刷新才能达到。"Agent 验证本次修改"这个核心场景在 Vue 2 上不成立。
- **建议**：编译成功后，通过自有回传通道通知 bootstrap 重新加载文档。bootstrap 可以长轮询同源的 `/__dsh_preview/build`，这不需要业务 WebSocket，也不会破坏现有的 Upgrade 准入。另外新增 `page_preview_refresh` 工具（只对自有预览有效），作为兜底。
- **验收**：修改 SFC 后，不需要人工操作，`status` 就会依次显示 `unverified` → `current`。

### 2.3 脱敏把短值替换得到处都是，诊断被破坏

- **证据**：`src/shared/redact.ts:43-47` 对所有非空 env 值做全文替换，没有长度和类型限制；`collectEnvValues` 会读取应用根下所有 `.env*` 文件，包括 `.env.example`。
- **复现**（本次实测）：env 为 `VITE_USE_MOCK=true`、`VITE_TIMEOUT=10`、`PORT=3000` 时，输入 `src/views/User.vue:10:5 ... expected true, got 3000`，输出变成 `src/views/User.vue:[redacted]:5 ... expected [redacted], got [redacted]`。
- **影响**：P0-2 的目标（让 Agent 拿到文件和行号）在大多数带 `.env` 的项目里会被抵消。
- **建议**：
  - 只把"像密钥的值"当作替换对象：键名匹配 `KEY|TOKEN|SECRET|PASSWORD|PASS|AUTH|COOKIE|SESSION|PRIVATE|CREDENTIAL|DSN`；或者值长度 ≥ 12 且不是纯数字、布尔值、普通 URL 的 origin。
  - URL 中的 userinfo 和 query 照常去除。
  - 不读取 `.env.example`、`.env.sample` 这类模板文件。
  - 单测要同时覆盖两个方向："短值不被替换"和"真实密钥被替换"。

### 2.4 从未在真实 DSH 中端到端跑通

- **证据**：`docs/development-progress.md` 中 P1-10 和 P1-12 都标着"代码完成，原生实机待验"；Phase 0 只验证过独立探针。插件从来没有作为产品安装进 DSH，也没有走完过"Agent 调用 → 审批弹窗 → 预览出现 → 修改代码 → current → 停止"这条完整链路。
- **影响**：目前 379 项测试全部基于合成的 SDK 环境和 headless Chrome。打包、安装、Client 加载和审批 UI 的实际行为都还未知。
- **建议**：下一轮的首要验收。需要 Aesc 授权：在独立的 DSH profile 中安装插件并重启。用 overview/web（Vue 3）走完整链路，并录屏或截图存档。
