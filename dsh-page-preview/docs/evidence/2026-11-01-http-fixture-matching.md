# HTTP fixture 匹配语义

2026-11-01：`matchFixture` 已补齐声明的 body 与路径参数匹配。它是纯匹配函数，不启动服务、不加载项目 handler，也不改变任何适配器的网络声明或默认 mock-only 门槛。

- origin：省略时仅当前预览 origin；声明时精确比较。method 不区分大小写。
- query：只约束显式声明的键值，保持既有字符串子集语义；HTTP 层解析和重复键处理尚待接入。
- body：省略表示不约束；声明时按 JSON 深相等，保留字段/类型，忽略对象键顺序但保留数组顺序。额外字段不匹配，null 与没有 body 不同；没有隐式子集匹配。
- path：完整 pathname 匹配，尾斜杠和段数有意义。`:name` 只能占一个完整非空路径段；字面段和实际段均解码一次。编码的斜杠可作为该参数的值，但不会重新拆成路径、文件路径或代码。参数名须合法且不能重复；query/hash 不能写在 path 中。模式语法错误明确抛出，畸形请求转义不匹配。
- 完全路径和参数路径同时命中，或两个 fixture 均命中，仍报告全部歧义索引；不按顺序或“更具体”规则选第一个。matched 结果新增 params，仅该纯内部返回类型变化，配置字段和 schema 不变。

测试覆盖对象键顺序、嵌套数组/类型/多余字段、空 body/null、Unicode 与百分号单次解码、空/多段/畸形参数、模式错误及重叠歧义。HTTP 中间件、请求体解析/大小边界、fixture 响应、项目 handler、业务路径分流和真实浏览器 Mock 仍待实现；本次通过不能代表 Mock 链路可用。
