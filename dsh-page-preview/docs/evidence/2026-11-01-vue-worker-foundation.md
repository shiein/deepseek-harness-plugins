# Vue 执行器基础设施

2026-11-01：为每预览独立执行器增加可选 ManagedProcessSpec.ipc 和 ManagedProcess.ipc，并让版本探测与工具链执行共用 resolveInstalledPackage 的实际位置查找。没有新增依赖，不改变默认托管项目命令的 stdio 或生命周期。

原因：Runner Root 按工作区复用；在其进程里持续加载项目工具链，会让 Node 模块缓存与环境状态跨预览保留。独立子进程符合方案 §6.5，仍由已有进程组、PID+启动时间及资源账本管理。项目控制消息使用专用 Node IPC；stdout/stderr 可能含凭据或任意 JSON，不能拿来判断协议或成功。

托管 IPC 从 spawn 起接收消息，首次订阅前保留启动消息，避免异步账本登记期间丢失启动通知；取消订阅后不积累无消费者的运行消息。只在显式 ipc:true 时存在，send 在断连后明确失败。具体执行器负责协议校验、订阅清理和原始输出排空，不允许用消息冒充端口或页面证据。

实际包查找只搜索声明工作区内的 node_modules 祖先；返回真实目录和合法安装版本，pnpm 链接目标可位于其真实包存储。局部包存在但版本无效时保留 unknown，不回退到祖先；损坏/断链/名称不符直接失败。查询不导入包入口，不自动安装或执行项目代码。

验证：macOS arm64 / Node 24.13.1。新增 4 项回归，完整 tests 260 / pass 260 / fail 0 / skipped 0，typecheck/build 退出 0。真实自有 Node 子进程在账本阻塞期间提前发启动消息，订阅后仍可收到；stdout 的伪 JSON 不进入 IPC；停止后进程账本为空，断连发送拒绝。包位置测试覆盖 hoist、pnpm、工作区边界、局部遮蔽及坏元数据。

这只是执行器基础：Vite start/专用 worker 协议、临时入口、真实产品链路与失败清理仍待接入，不据此提升 Vue 支持范围。
