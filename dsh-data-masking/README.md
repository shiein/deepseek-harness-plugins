# 数据脱敏（dsh-data-masking）

在 DSH 把请求发给模型之前，把区域、部门、术语、人员、地址、特定 ID 段等敏感信息替换成占位符；模型回复流回本机时再把占位符还原成原文。模型服务商只看到占位符，而界面、会话记录、改代码和写文件用的都是真实值。

```
你的原文      请风控二部的张三丰确认上线
模型收到      请{{DEPT_3fa9c1}}的{{PERSON_8b20e4}}确认上线
模型回复      已通知 {{PERSON_8b20e4}} 确认
你看到的      已通知 张三丰 确认
```

## 入口

界面在会话的**右侧栏**里，和页面预览、工作区文件、终端一样：打开右侧栏，在"开始"引导页点"数据脱敏"。面板顶部显示脱敏开关，以及当前会话是否受保护；拦截记录默认只显示本会话的，可以切换为全部。词库和规则对所有会话生效。面板在窄宽度下自动改为单列布局。

## 功能

| 功能 | 说明 |
|---|---|
| 词库分类 | 默认有区域、部门、术语、人员、地址五类，可新增自定义分类；每行一个词条，长词优先匹配 |
| ID 段与正则 | 用正则匹配特定格式或号段，比如 `EMP-88\d{4}`；保存时会校验，无法编译、能匹配空串、带嵌套量词的正则会被拒绝 |
| 内置识别 | 手机号、身份证号（校验位必须正确）、邮箱，默认关闭；会自动跳过 `example.com` 这类示例域名 |
| 白名单 | 列在这里的值永不脱敏，用于处理误伤，或者模型必须看到原文的值 |
| 出网工具 | `web_search`、`web_fetch` 这类会把参数发到外部的工具，参数里含受保护数据时会被拦截；支持用 `*` 结尾写前缀，比如 `mcp__remote__*` |
| 试一试 | 粘贴文本后实时看到模型会收到什么；用的是正在编辑的规则，还没保存也能试 |
| 拦截记录 | 每个会话里某个值第一次出现时记录一条；另外记录被阻止的请求和被拦截的工具调用。只保存类别、长度和打码预览，比如"张\*\*"，不保存原文 |

占位符格式是 `{{代号_6位十六进制}}`。代号表示类别，模型因此知道这是部门还是人名；后缀是用本机密钥对原值计算的 HMAC。同一个值永远得到同一个占位符，所以：

- 模型能理解多处指代的是同一个对象；
- 重发历史时，请求前缀逐字节不变，服务商的 prompt 缓存照常命中；
- 模型此前输出的占位符（包括 thinking）回放时和它当初生成的内容完全一致。

## 覆盖范围

| 通道 | 状态 |
|---|---|
| DSH 原生会话、子 Agent、会话标题生成、自动压缩 | 覆盖。所有经过 `ctx.llm` 的请求都会脱敏，跟具体是哪家模型无关。主会话、子 Agent、标题生成已端到端验证；自动压缩走同一个 `ctx.llm.stream`，是按代码推断的 |
| 请求内容 | `system`、所有消息的所有字符串内容，包括插件自定义的块类型、工具结果、历史里的工具调用参数、推理内容、附件文件的名称和路径文本，以及工具描述 |
| Session Log 上传（`dsh_session_log`） | 只要一个会话在脱敏开启时请求过模型，它就永远不随请求上传原始日志，之后关掉脱敏也一样。**但关掉脱敏后，消息本身（包括这个会话的完整历史）会以原文发给模型** |
| 出网工具 | 参数含受保护数据时拦截，拦截原因里不会出现原值 |
| ACP Agent | **不覆盖**。ACP Agent 自己调用自己的模型，请求不经过 DSH |
| 反馈上报（OTel） | **不覆盖**。提交反馈时会导出原始会话，敏感会话请不要提交反馈 |
| 图片 | 不覆盖，文本规则识别不了图片里的内容 |

## 设计与取舍

**拦截点。** 插件在 `llm/stream` waterfall 上挂一个监听器。这个 waterfall 的 `next()` 不接收参数，没法把改写后的请求往下传。所以监听器不调用 `next()`，而是把脱敏后的副本直接交给 `LlmRuntime.adapterStream()`，也就是适配器分发的最后一道入口，再把返回的流包上一层还原逻辑。由此带来两点：

- `adapterStream` 不是公开接口，DSH 升级后可能改名或删掉。插件每次处理请求都会检查它还在不在；不在时，只要脱敏开着，就阻止所有请求，不会把原文发出去。
- 本监听器后面注册的 `llm/stream` 监听器不会再执行。DSH 0.2.2-rc.1 内置的两个监听器（session-checkpoint-policy、session-title）都在基础 bundle 里，比本插件先执行，不受影响。

**规则文件损坏时的修复。** 界面会以默认分类作为编辑起点，填写并保存即可覆盖损坏的文件；保存后脱敏保持开启，因为损坏前的开关状态已无从得知。错误信息只报告 JSON 语法错误的位置，不会引用文件内容，以免把词条写进日志。

**失败即阻止。** 下面任何一种情况，只要脱敏开着（规则读不出来时也当作开着），模型请求都会以 `DATA_MASKING_BLOCKED` 结束，不会发给服务商，也不会自动重试：

- 规则文件解析失败或校验不通过（不会退化成"当作没有规则"）；
- 受保护会话列表读不出来；
- `adapterStream` 或文件投影接口缺失；
- Session Log 上传服务存在，但本插件的排除规则还没注册上；
- 脱敏过程中抛出异常。

**还原。** 每个内容块各自保留一个小缓冲区：可能是占位符开头的文本先扣住不发，等下一个分片到了或者块结束再处理。所以占位符被拆在两个分片里也能正确还原。工具参数是原始 JSON 字符串，还原时会对原值做 JSON 转义，私钥里的换行、引号这类字符不会把 JSON 弄坏。`finish.replayState` 是服务商自己的不透明数据，原样透传：它还会发回同一个服务商，那边就应该继续看到占位符。

**模型自造或改写了占位符。** 如果工具参数里出现一个属于已配置类别、既不是本次请求发出的、也没在请求原文里原样出现过的占位符，说明模型自己编造或改写了它，没法还原。这次工具调用会被拒绝，并告诉模型要原样使用对话里已有的占位符，避免把占位符写进文件。文件或文档里本来就有的占位符样式文本（比如本 README 里的示例）会被记住，不会误拦。

## 数据存放

所有数据在 `$DSH_HOME/data-masking/`（默认 `~/.dsh/data-masking/`），文件权限 0600：

| 文件 | 内容 |
|---|---|
| `rules.json` | 词库、规则和开关。**这是唯一包含敏感词原文的文件** |
| `secret.key` | 生成占位符用的 HMAC 密钥，首次运行时随机生成 |
| `protected-sessions.json` | 曾在脱敏开启时请求过模型的会话 ID |
| `history.jsonl` | 拦截记录，不含原文，最多保留 2000 条 |

这些文件不放在插件目录，也不写进 `cordis.patch.yml`，所以不会跟着仓库或 profile 配置被提交、被备份。网盘备份插件默认的同步范围不包含这个目录。

原文只在处理请求的过程中留在内存里。占位符和原值的对照表每次请求现建，因为每次请求都带着完整历史，不需要落盘。

## 接口

只接受本机回环地址的同源请求：

- `GET  /api/dsh-data-masking/state`：状态、规则、统计
- `POST /api/dsh-data-masking/rules`：校验并保存规则（不会改动开关状态）
- `POST /api/dsh-data-masking/toggle`：`{ "enabled": true | false }`
- `POST /api/dsh-data-masking/preview`：`{ "text": "...", "rules"?: 草稿规则 }`
- `GET  /api/dsh-data-masking/history?limit=&before=`
- `POST /api/dsh-data-masking/history/clear`

没有 Web 服务时（比如 headless），脱敏照常工作，只是不挂载这些接口。

## 限制

- 模型看到的是占位符。需要知道值本身的任务会变差，比如判断某个 ID 的格式、翻译或纠正部门名。这类值可以加白名单，或者临时关闭脱敏。
- 词库会误伤：太短、太常见的词会让模型丢掉上下文。词条要尽量具体。
- 正则只做了静态检查（嵌套量词、能匹配空串）。JavaScript 正则没有超时机制，复杂正则仍有回溯过慢的风险。
- `bash` 里的 `curl` 这类出网操作，插件识别不出来。
- 关闭脱敏开关后，所有会话的后续请求都以原文发送，包括之前受保护会话的历史消息；界面上关闭前会提示确认。
- 停用或卸载插件后，脱敏和 Session Log 上传保护都会失效；之前受保护的会话会在下一次请求时补传积压的日志。所以，如果插件只是暂时停用，建议同时关掉"设置 → 通用 → 在使用官方模型 API 时上传 Session Log"。

## 测试

```bash
npm test                 # 单元测试：引擎、在任意位置拆分的流式还原、请求遍历、各种阻止情形、工具拦截
npm run test:e2e         # 端到端：在临时 DSH_HOME 里启动本机安装的 DSH（headless），对接本地 mock 服务，共 6 个场景
```

端到端测试检查发给服务商的请求体里没有原文、`dsh_session_log` 没有出现、结果文件里是还原后的原值，并覆盖这几个情形：关闭脱敏后恢复受保护会话不会补传日志、规则文件损坏时阻止请求、`web_fetch` 被拦截、子 Agent 的请求同样脱敏。它不会动你的 `~/.dsh`。
